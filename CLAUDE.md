# Payment Panel automation — conventions for AI changes

Playwright + TypeScript tests of the Ejara Payment Panel (web). Its test plan lives in the **Ejara Automation Tool**;
this repo follows it (spec §6.9.5 of the tool). Changes made by AI always go through a pull request reviewed by QA.

## Structure
- `test-plan/*.json` — **generated by the tool, never edited by hand.**
- `tests/<module>/` — one `test()` per case, its ID first: `test('<TC ID> <what it checks>', async (…) => { … })`.
  Modules: auth, smoke (navigation), transactions, payments, settings.
- `src/pages/` — page objects. `src/fixtures/` — fixtures. `src/reporting/` — results for the tool's runner.
- `docs/inferred-spec.md` — what is confirmed vs. inferred about the panel (there is no written spec).
- `ejara-automation.json` — what the tool reads (commands, folders).

## What a task may change
A task names its TC IDs. Change only the tests of those TC IDs in `tests/` and the page objects they use in
`src/pages/`. `playwright.config.ts`, fixtures, reporting, scripts and other modules' tests need a task that says so.
Never edit `test-plan/`.

## Rules
- A test checks its case's steps and expected results. Where the case says INFERRED / to confirm, keep the test
  skipped with the reason until QA confirms the behaviour; never invent an expectation.
- **Money:** Make Payment only on testbox, with the test customer of the case, and only once QA has confirmed it's
  safe to run unattended. Never switch "Sync with Nellys Coin" or "Switch Live" on.
- Tests share one admin session and run sequentially (`workers: 1`).
- No secrets in code: credentials come from `.env`.

## Before the pull request
`npm run typecheck`, `npm run test:unit`, then run the changed tests once on testbox and attach the result.
